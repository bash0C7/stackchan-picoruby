# picoruby-stackchan-robot

Robot engine of the StackChan CoreS3 firmware: a DSL for faces, touch reactions and periodic work, the cold-boot sequence, and the BLE peripheral that serves dRuby.

## Usage

```ruby
StackChan.robot do |bot|
  bot.face :neutral
  bot.face :smile,  mouth: 8
  bot.face :closed, eyes: :closed, mouth: :none

  bot.face_index "0" => :neutral, "1" => :smile

  bot.on_touch(:back) { |r| r.face(:smile); r.led(:both, [0, 60, 0], flash: 300) }
  bot.every(5000) { |r| r.blink(150) }

  bot.release_after 15_000
end.run
```

`:neutral` and `:closed` faces are required, and every `face_index` entry names a defined face.
`on_boot`, `on_touch`, `on_frame`, `remote` and `every` take a block that receives the robot handle.
`run` sleeps 5 s, runs the cold-boot, sleeps 3 s, starts the peripheral, calls the `on_boot` handlers, advertises, and does not return.
Device constants (`ILI9342`, `I2C`, `BLE`, ...) are not read in class bodies.
The peripheral takes BLE data only through the event queue `pop` and `pop_write_value`.
The robot drops the central after `release_after` ms without a dRuby write or CCCD write.
